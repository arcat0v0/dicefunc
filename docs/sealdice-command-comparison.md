# DiceFunc 与 SealDice-Core 指令兼容审计

本文对比当前 DiceFunc 与 SealDice-Core 基线提交 `4493693`。对齐目标是命令入口、参数、状态变化和失败语义，不复制 SealDice 文案，也不把同名命令视为已经兼容。

## 1. 当前结论

DiceFunc 已覆盖 COC7、DND5E、角色卡、先攻、牌堆和跑团日志的主要日常闭环。上一版审计列出的高风险入口问题已经修正：

- `.ra侦查`、`.st力量50`、`.en侦查` 等紧凑 Unicode 参数可进入对应处理器。
- 裸 `.ra/.rc`、缺失技能、SAN、HP、MaxHP、未知牌堆、未知种族和未知规则集会明确失败，不再用虚构默认值继续执行。
- `.check` 只说明 SealDice 官方实例防伪在本部署不可用，不再映射到 `.ra`。
- `.init end` 推进回合，`.init clr` 才清空先攻列表。
- `.setcoc` 同时切换 COC7 路由；`.userid` 分开显示发送者、会话和场景标识。
- 帮助内容由当前已实现语法维护，不宣称牌堆热重载等不存在的能力。

这仍不是 SealDice 的逐字节替代品。DiceFunc 运行在 Cloudflare Workers 和 QQ 官方机器人上，采用固定的规则模块、配置包、D1 权威状态、私有 R2 归档和受控主动消息；SealDice 的常驻进程管理、运行时扩展装卸、任意转发和完整 RollVM 不属于兼容承诺。

## 2. 全局入口与路由

当前入口支持：

- 前缀 `.`、`。`、`!`、`！`、`/`。
- 显式空格参数和已注册命令后的紧凑 Unicode 参数。
- 有界的命令级重复语法；状态命令仍由各处理器决定是否接受重复，不能把执行器级重复理解为任意状态操作的事务循环。
- COC7 与 DND5E 同名 `.ra/.rc/.st` 通过会话 `ruleSet` 路由。
- 群内代骰只读取已签名事件中提及的参与者，并从 D1 加载该参与者在当前群绑定的角色卡。
- 群聊暗骰只通过可信 C2C 绑定投递；私聊失败时绝不把结果回落到群内。

DiceFunc 的表达式解析器覆盖日常骰式、算术、括号、选高选低和 DND 优劣势，并支持在骰式中读取当前角色卡的数值属性；COC7 的 `DB` 可按力量与体型推导。仍不承诺 SealDice RollVM 的逻辑表达式、模板变量、函数、控制流及其他扩展方言。

## 3. 已对齐的核心命令

### 3.1 COC7

| 能力 | 当前入口 | 当前契约 |
|---|---|---|
| 普通检定 | `.ra/.rc` | 支持技能或显式目标、困难/极难、奖惩骰、修正值、原因、命令内重复；`.rc` 强制规则书判定。缺失目标明确报错。 |
| 暗骰检定 | `.rah/.rch` | 复用可信 C2C 绑定；群内只显示不含结果的投递状态。 |
| 对抗检定 | `.rav/.rcv` | 分别判定双方成功等级，再按技能值处理同级结果。 |
| 代骰 | 检定命令中的群成员提及 | 只允许事件中已验证的被提及成员，并读取其当前群角色卡。 |
| SAN 检定 | `.sc` | 支持奖惩骰、显式检定值、`--cap`、`--half`、房规大失败损失和角色卡写回。 |
| 成长 | `.en` | 支持批量技能、角色卡取值、独立失败/成功成长表达式和原子写回。 |
| 房规 | `.setcoc` | 支持内置 `0-5` 与 `dg`，并切换会话到 COC7。 |
| 制卡与症状 | `.coc/.ti/.li` | 提供受限、确定版本的数据表；不复制 SealDice 文案。 |

### 3.2 DND5E

| 能力 | 当前入口 | 当前契约 |
|---|---|---|
| 属性、技能、豁免 | `.st`、`.ra/.rc` | 计算技能父属性、熟练倍率和豁免；检定支持优劣势、表达式、重复、原因和可信暗骰。 |
| 先攻 | `.ri`、`.init` | `.ri` 负责单人或批量掷先攻；`.init` 负责查看、设置、删除、推进和清空。 |
| 生命状态 | `.hp`、`.st HP...` | 共享 MaxHP、HP、TempHP、死亡豁免和重伤不变量；支持骰式伤害与治疗。 |
| 临时加值 | `.buff/.dbuff` | 支持属性加值、熟练倍率加值、删除和清空，并参与计算检定。 |
| 法术位 | `.ss/.dss/.法术位` | 支持批量初始化、设置、消耗、恢复、清空和环阶增减。 |
| 施法 | `.cast/.dcast` | 原子消耗指定环阶法术位，法术位不足时不写状态。 |
| 死亡豁免 | `.ds/.死亡豁免` | 支持优势、劣势、骰式修正、手工成功/失败计数，并与 HP 状态联动。 |
| 长休 | `.longrest/.rest/.长休/.dlongrest` | 要求已有 MaxHP；恢复 HP 与法术位，清空临时 HP 和死亡豁免。 |
| 制卡 | `.dnd/.dndx` | 生成自由分配或带属性名的六维结果。 |

DiceFunc 没有迁移 SealDice 的完整 DND 模板系统、名片 API 或任意第三方扩展状态。

### 3.3 角色卡

`.pc/.char/.ch` 当前支持：

- `new` 创建并绑定角色卡。
- `list/show` 列出当前用户拥有的全部角色卡并标记当前绑定。
- `save` 保存当前卡副本。
- `load/tag` 按名称或 ID 绑定本人角色卡，拒绝缺失或他人角色卡。
- `rename` 重命名本人角色卡。
- `del/delete` 以版本守卫删除本人角色卡及相关绑定。
- `untag/release/unbind` 解除当前场景绑定。

角色卡按 bot、所有者和场景隔离。`.nn` 只改本地角色卡名称，不调用 QQ 群名片接口。

### 3.4 牌堆、日志与查询

| 命令 | 当前能力 | 明确边界 |
|---|---|---|
| `.draw/.deck` | 抽牌、列表、键列表、搜索、当前无放回状态重置。 | 未知牌堆报错；内置资源不可在运行时 `reload`。 |
| `.log` | `new/on/pause/halt/end/list/get/stat/export/del`。 | `halt` 关闭但不归档；`end` 进入归档；`del` 先撤销下载授权，再由持久任务收敛删除 R2 和 D1 正文。 |
| `.find/.查询/.査詢` | 关键字搜索、稳定条目 ID、分组列表和分页。 | 当前是受版本控制的小型规则词表，不是 SealDice 全量帮助资源。 |
| `.modu/.魔都/.cnmods` | 提供当前受控模组查询入口。 | 不执行远程脚本或下载不可信扩展。 |

日志下载保持 DiceFunc 的私有 R2 边界：只有冻结且完整的归档可下载，授权短时有效，审计失败时拒绝正文。

## 4. 管理、消息与低成本兼容项

### 4.1 群内管理替代

`.black/.ban` 是显式的群作用域替代入口：

- 仅当前群主可用。
- 目标必须来自当前已签名事件中的群成员提及。
- 支持查看、拒绝、信任和删除策略。
- D1 唯一键包含 bot、群和目标 principal；策略不会泄漏到其他群或其他 bot。
- 写入和删除都使用版本守卫。

`.dismiss/.botlist/.master/.randalgo/.ext` 依赖 SealDice 常驻进程、运行时扩展或算法切换模型。它们会返回明确的 `system.unsupported`，不会伪造成功或产生状态副作用。

### 4.2 消息功能替代

`.send/.reply/.welcome/.team` 依赖主动消息权限、群成员事件或可信骰主收件身份。当前 QQ 官方机器人部署没有足够协议保证，因此这些入口返回 `messaging.unsupported`：

- 群内处置使用 `.black`。
- 固定欢迎语与自定义回复通过经 Schema 校验的配置包发布。
- 不把私聊失败的内容公开到群内，也不把 OpenID 当作跨场景通用身份。

`.alias/.a/.&`、`.text`、`.ob`、`.sn`、`.command`、`.stat/.hiy` 属于未启用的聊天侧扩展，入口会明确返回 `extension.unsupported`。

### 4.3 已实现的低成本项

- `.ping` 返回当前命令处理状态。
- `.who` 从输入选项中随机选择并返回稳定结构化结果。
- `.gugu` 同时支持 `.咕咕`。
- `.modu` 同时支持 `.cnmods`。
- `.name` 默认生成五个名称，支持中、英、日类型、性别和数量。
- `.namednd` 支持达马拉、卡林珊、莱瑟曼、受国、精灵、矮人、兽人、海族和地精九类名称。

## 5. 非核心规则扩展排期

这些命令已经注册为可识别的显式失败入口，当前不会落入“未知命令”或错误规则处理器：

| 批次 | 命令 | 决策与进入条件 |
|---|---|---|
| 当前版本 | `.rsr/.ek/.ekgen/.dx/.dxh/.ww/.w/.wh/.wwh/.jsr/.drl/.drlh` | 返回 `ruleset.unsupported`，无状态副作用。 |
| 下一规则扩展批次 | `.rsr` | 仅在确定实际目标规则、取得可授权的数据与模板并补齐角色状态模型后迁移；优先级高于其他非核心规则。 |
| 后续内容包批次 | `.dx/.ww/.jsr/.drl` 及别名 | 作为独立构建时可信规则模块评审；每个模块必须有解析、预算、角色状态和兼容用例，不能共用模糊的万能处理器。 |
| 暂不排期 | `.ek/.ekgen` | 需求和数据许可未确定；保持显式不支持，不预建空壳接口。 |

任何批次都必须先满足：规则来源与许可明确、配置 Schema 固定、随机与输出预算受限、D1 状态不变量完整、公共命令入口有兼容用例。没有这些条件时不承诺日期。

## 6. 仍然存在的有意差异

- 官方 `.check` 防伪依赖 SealDice 官方签名体系；DiceFunc 不冒充官方实例。
- `.deck reload` 不存在，因为 Workers 没有可变本地文件牌堆；资源通过不可变配置包发布。
- `.nn/.sn` 不修改 QQ 群名片。
- `.log export` 使用私有 R2 和短时授权，不提供公共染色上传、邮件发送或永久公共链接。
- 运行时扩展装卸、进程重启、二维码登录、多平台 ID 合并和任意主动消息不在产品范围。
- 帮助、症状表、姓名表和回复文字是 DiceFunc 自有内容，不复制 SealDice 原文。

## 7. 兼容验收矩阵

验收必须检查处理器、结构化结果、随机流、更新、权限和失败类型，不能只检查“有回复”。当前最低矩阵如下：

| 入口 | 必须观察的结果 |
|---|---|
| `。ra` | 格式或缺失目标错误；不掷骰、不写状态。 |
| `.ra侦查`、`.ra 困难侦查`、`.ra b 侦查`、`.ra p2 侦查` | 紧凑入口、难度和奖惩骰正确；技能来自当前 COC7 卡。 |
| `.ra 3#p 侦查`、`.ra 侦查+10 原因` | 命令内重复、修正和原因正确；随机消费次数固定。 |
| `.rc 侦查`、`.rah 侦查`、`.rav 侦查65 潜行55` | 规则书判定、可信私聊和对抗结果分别进入对应处理器。 |
| `.st力量50敏捷60`、`.st show`、`.st HP-1d6` | 紧凑批量录入、读取和骰式 HP 变化使用同一角色状态。 |
| `.pc save 调查员`、`.pc list`、`.pc load 调查员` | 保存、列出和重新绑定都校验所有者与版本。 |
| `.sc b 1/1d6 --half --cap=2` | SAN 奖励骰和损失上限生效，写回一次。 |
| `.en侦查`、`.en 侦查 图书馆使用` | 单项与批量成长分别消费固定随机流并原子写回。 |
| `.ri =1d10+3 王五, +2 李四, 12 张三` | 批量先攻解析、掷骰和排序正确。 |
| `.init del 张三`、`.init end`、`.init clr` | 删除、推进、清空语义互不混淆。 |
| `.ss init 4 3 2`、`.ss 3环-1`、`.cast 3` | 初始化、直接变更和施法消耗共享法术位状态。 |
| `.ds +1d4`、`.longrest` | 死亡豁免修正生效；长休恢复并清零相关状态。 |
| `.draw 不存在的牌堆` | 明确错误且无状态更新。 |
| `.check` | 明确说明官方防伪不可用，不执行规则检定。 |
| `.userid` | 分别返回发送者、会话和场景标识。 |
| `.black add @成员`、`.black rm @成员` | 只写入或删除当前 bot、当前群、被提及 principal 的策略。 |
| `.send`、`.master`、`.rsr` | 分别返回消息、系统管理、规则扩展的显式不支持类型，且无副作用。 |

持久化验收还必须覆盖：D1 batch 冲突整批回滚、角色库所有权、群作用域策略、日志删除任务、R2 对象收敛删除、暗骰发送失败不泄露结果，以及重试不重新掷骰或重复扣减。
