# DiceFunc 与 SealDice-Core 指令处理逐项审计

本文档逐项对比当前 DiceFunc 指令实现与 SealDice-Core 基线提交 `4493693`。重点是用户实际输入如何被识别、参数如何解释、读取和修改哪些状态，以及同名指令是否真的兼容；不把“注册了同名命令”视为功能对齐。

## 1. 范围、口径与结论

### 1.1 审计口径

- DiceFunc 依据 `packages/core/src/application/execute-command.ts`、`packages/core/src/application/commands.ts` 及其直接调用的领域模块。
- SealDice 依据提交 `4493693` 中 `dice/builtin_commands.go`、`dice/ext_*.go` 与 `dice/ext_core.go`。
- SealDice 同一个 `CmdItemInfo` 下的多个命令键按一个“语义指令组”统计，别名仍全部列出。
- 当前 DiceFunc 注册了 **33 个主命令、29 个别名，共 62 个命令键**。
- SealDice 基线包含 **62 个语义指令组、110 个扩展内注册项（105 种不同命令拼写）**；同名 `.ra/.rc/.st` 会在不同规则扩展中重复注册。
- “部分兼容”仅表示存在重叠能力，不表示 SealDice 的常用语法、状态副作用或错误行为已兼容。
- 本文是当前源码的静态审计，不把 README、旧文档、帮助文本或尚未部署的代码当作线上验证证据。

### 1.2 总体结论

当前差距不是简单的“缺少若干边缘指令”，而是核心兼容链路仍有系统性问题：

1. **命令识别本身不兼容。** 紧凑中文参数无法通过粘连识别，`.ra侦查`、`.st力量50`、`.en侦查` 会被当作未知命令。
2. **同名命令经常只有表面相似。** `.ra`、`.st`、`.pc`、`.init`、`.ss`、`.sc`、`.en`、`.ds` 的常用 SealDice 语法、角色卡读取、代骰、错误处理或副作用均不完整。
3. **存在语义冲突。** DiceFunc 把 `.check` 注册成 `.ra` 别名，而 SealDice 的 `.check` 是官方防伪校验；DiceFunc 的 `.init end` 清空战斗，SealDice 的 `.init end` 推进到下一行动者。
4. **多个默认回退会静默制造错误结果。** 缺失技能、SAN、HP 或参数时，当前实现会使用 50、20、10 等默认值继续执行，而 SealDice 通常报格式、未录卡或类型错误。
5. **帮助文本不能作为当前实现说明。** `.help` 展示了多项未实现语法，并遗漏了已实现子命令；用户会按帮助输入后得到错误结果。
6. **扩展路由模型没有等价替代。** SealDice 允许 COC7 与 DND5E 扩展分别提供同名 `.ra/.rc/.st`；DiceFunc 只有单一注册项并在处理器内部按 `conversation.ruleSet` 分支，且 `.setcoc` 不会切换 `ruleSet`。

因此，当前项目不能按“核心指令已基本替代 SealDice”来描述。制卡、基础骰点、发疯表等孤立能力可用，但 COC/DND 的日常角色卡工作流尚未闭环。

## 2. 全局指令识别与执行差异

### 2.1 DiceFunc 当前识别流程

当前执行器依次执行：

1. `trim()` 消息文本。
2. 解析消息开头的全局重复前缀 `N#` 或 `N＃`，上限 10。
3. 剥离一个显式前缀：`.`、`。`、`!`、`！`、`/`。
4. 以空白切分命令名和参数，直接查注册表。
5. 直接查找失败后，尝试“命令名与首参数粘连”的最长前缀匹配。
6. 检查机器人启用状态和 `all/groupHost/diceMaster` 权限。
7. 调用处理器，汇总 `results/updates/replies/logItems`。

这与 SealDice 的扩展激活、同名命令优先级、`CmdArgs`、代骰、关键字参数和专用多轮解析不是同一套语义。

### 2.2 紧凑中文参数无法识别

粘连匹配只接受参数首字符符合：

```text
^[\d+-\w优劣優]
```

JavaScript 的 `\w` 只覆盖 ASCII 字母、数字和下划线，不覆盖普通汉字。因此：

| 输入 | 当前源码结果 | SealDice 预期 |
|---|---|---|
| `.ra 侦查` | 能找到 `.ra` | 能执行 |
| `.ra侦查` | `ra侦查` 不是已注册命令，粘连参数首字“侦”不被接受，返回未知命令 | 能执行侦查检定 |
| `。ra侦查` | 同上；全角句号能剥离，但后续仍失败 | 能执行 |
| `.st力量50` | 未知命令 | 能录入属性 |
| `.en侦查` | 未知命令 | 能进行成长检定 |
| `.ra50` | 能按粘连形式识别，因为参数以数字开头 | 能执行 |
| `.rab侦查` | 能先按 `ra` 粘连，但当前 COC 参数器不认识单独 `b`，最后会退化成普通技能名/默认值路径 | 奖励骰检定 |

这是用户感知“`.ra` 识别不了”的直接高风险来源之一。

对**字面输入 `。ra`**，当前源码在机器人已启用且确实部署了这份代码时会找到注册项，但会错误地执行“名称为检定、目标值 50”的检定；SealDice 会返回格式错误。若线上字面 `。ra` 完全无响应，当前源码还存在另一条静默路径：机器人关闭时，`.ra` 因 `allowedWhenDisabled: false` 被直接丢弃。若线上返回未知命令，则还需要核对部署版本或事件进入 `CommandExecutor` 前的文本；静态源码本身不会对已启用会话中的字面 `。ra` 返回未知命令。

### 2.3 重复执行模型不等价

DiceFunc 的 `N#` 是执行器级递归：每轮都使用同一份输入快照，最后简单拼接所有更新。它适合无状态 `.r`，但不适合修改状态的命令；多轮 `.st/.en/.sc/.ds/.draw` 可能产生多个使用同一 `expectedVersion` 的更新，无法表达逐轮读取上一轮结果的语义。

SealDice 的 `EnableExecuteTimesParse` 只对指定指令启用，并由指令内部控制每轮表达式、输出和状态。因此不能把 DiceFunc 的全局 `N#` 当作 SealDice 多轮语法已经兼容。

### 2.4 规则扩展路由不等价

- SealDice 的 COC7 和 DND5E 扩展各自注册 `.ra/.rc/.st`，当前激活扩展和规则模板决定具体处理器。
- DiceFunc 只有一个 `.ra` 处理器：仅当 `ruleSet === "dnd5e"` 时走 DND 分支，其余任意字符串都走 COC 分支。
- DiceFunc 只有一个 `.st` 处理器；COC7 才执行别名归一化，DND 没有 SealDice 的计算技能、熟练项和临时加值模型。
- `.setcoc` 只修改 `cocRule`，却回复“COC7规则扩展已自动开启”；它没有把 `ruleSet` 切换为 `coc7`。在 DND 会话执行 `.setcoc 2` 后，`.ra` 仍走 DND 分支。
- `.set rule <任意文本>` 未校验规则名，可以把会话写入未知规则；此后 `.ra` 会因“不等于 dnd5e”而走 COC 分支。

## 3. DiceFunc 现有 33 个主命令逐项对比

状态含义：

- **接近**：主要用户路径相似，仍可能有别名、文案或数据集差异。
- **部分**：存在可用子集，但常用 SealDice 语法或副作用缺失。
- **冲突**：同样输入会执行不同含义或危险副作用。
- **额外**：DiceFunc 自有能力，SealDice 基线没有同名语义。

### 3.2 COC7 与 DND5E

| DiceFunc 主命令与别名 | 权限/关闭时 | 当前实际行为 | 对比结论与关键差异 |
|---|---|---|---|

| `.dnd`：`dnd5e` | all / 不可用 | 最多 10 组 `4d6k3` 自由分配数组并合计。 | **接近**。核心生成方式接近；`dnd5e` 是 DiceFunc 额外别名。 |

### 3.3 牌堆、查询与娱乐

| DiceFunc 主命令与别名 | 权限/关闭时 | 当前实际行为 | 对比结论与关键差异 |
|---|---|---|---|
| `.draw` | all / 不可用 | 从内置牌堆按会话持久化无放回抽取，默认 tarot，最多 10 张。 | **部分且有静默回退**。SealDice 从文件牌堆抽取，支持嵌套引用、骰式宏、重复和牌堆搜索。DiceFunc 输入未知牌堆时会静默改抽 tarot，使 `deck.not_found` 分支实际不可达。 |

## 5. 别名、权限、状态与副作用复核

### 5.1 当前 DiceFunc 别名中的兼容问题

| DiceFunc 别名 | 问题 |
|---|---|
| `check -> ra` | 与 SealDice 官方防伪 `.check` 直接冲突。 |
| `coc6 -> coc` | 实际仍生成 COC7 卡，名称误导。 |
| `deck` 独立命令 | SealDice 中 `deck` 是 `draw` 别名；相同输入可能走完全不同逻辑。 |
| `ri -> init` | SealDice 把掷先攻和列表管理分开；DiceFunc 合并后丢失批量语法。 |
| `id/uid -> userid` | SealDice 基线未注册这些别名；额外别名本身无害，但当前输出对象错误。 |
| `spell -> ss`、`rest -> longrest`、`initiative -> init` | DiceFunc 额外别名；不能替代缺失的 SealDice `dss/法术位`、`长休/dlongrest` 等别名。 |
| `sancheck -> sc`、`nick -> nn`、`dnd5e/dnd5ex` | DiceFunc 额外别名；需要在帮助中标明为本项目扩展，避免被误认为基线兼容。 |

### 5.2 当前 DiceFunc 权限模型

注册表层面只有三种权限：`all`、`groupHost`、`diceMaster`。当前默认注册项中：

- `groupHost`：`.set`、`.bot`、`.setcoc`；骰主也可通过。
- `all`：其余 30 个主命令。
- 没有默认注册项直接声明 `diceMaster`；`.help reload` 和 `.log export` 等在处理器内部再检查权限。
- 机器人关闭时仍可用：`.rhbind`、`.help`、`.set`、`.bot`、`.setcoc`、`.find`。
- 其余命令在关闭时直接返回空结果，没有“机器人已关闭”的反馈。

与 SealDice 相比，当前缺少：平台管理员级别、Master 指令体系、@代骰授权、群/私聊限制、命令级 mention 检查、扩展启用状态和不同子命令的细粒度权限。

### 5.3 静默默认值与错误处理

以下行为会让用户得到“看似成功、实际基于虚构数据”的结果，应优先改为明确错误：

| 路径 | 当前默认 | 风险 |
|---|---:|---|
| 裸 `.ra` 或 COC 技能不存在 | 目标值 50 | 把格式错误或未录技能伪装成有效检定。 |
| DND `.ra <未知技能>` | 属性值 10，调整值 0 | 把未录技能伪装成普通 d20。 |
| `.sc` 无 SAN | SAN 50 | 进行不可持久化的虚构理智检定。 |
| `.en` 技能不存在 | 技能 50 | 报告虚构成长；无卡时也无法保存。 |
| `.hp` 缺 HP/MaxHP | 20/20 | 读取或写入并不存在的角色生命值。 |
| `.longrest` 缺 MaxHP | 20 | 长休会创建/覆盖 HP。 |
| `.init set <名称> <非法值>` | 10 | 输入错误仍加入先攻。 |
| `.draw <未知牌堆>` | tarot | 用户请求错误牌堆却得到塔罗结果。 |
| `.namednd <未知种族>` | 精灵池 | 输出标签仍显示用户输入的种族，内容却是精灵名字。 |

### 5.4 状态副作用与组合问题

1. `.setcoc` 不切换 `ruleSet`，回复与实际状态不一致。
2. `.pc load` 不验证目标卡存在或归属，先写绑定关系。
3. `.pc save` 同名覆盖不是更新，而是再次以 `expectedVersion: 0` 创建。
4. `.userid` 把会话外部 ID 标成用户 ID。
5. `.init end` 与 SealDice 含义相反，会造成破坏性误操作。
6. `.help reload` 没有状态副作用，只返回成功文本。
7. `.deck reload` 没有资源重载副作用，只重置会话牌堆。
8. 执行器级 `N#` 对状态命令复用同一快照，无法保证逐轮状态演进。
9. 当前 `.ra` 读取属性时不走 `.st` 的别名归一化；例如 COC 卡用英文别名录入后可能已经规范化为中文键，而 `.ra spot` 仍按 `spot` 原键查找并回退 50。

## 6. 修复优先级

### P0：先让命令入口和危险语义正确

1. 修复粘连识别，使 `.ra侦查`、`.st力量50`、`.en侦查` 等汉字参数可达对应处理器，并覆盖全角前缀。

7. 移除未知牌堆、未知种族、未知技能/SAN/HP 的静默默认回退。
8. 重写 `.help`，只展示处理器真实支持的语法。

### P1：补齐 COC7 日常闭环

### P3：按产品范围选择性迁移
